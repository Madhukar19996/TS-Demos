Why TypeScript? → Type Safety 🛡️

Most Important Concept of Day 1! This is the core reason TypeScript exists.

❌ JavaScript — Dynamically Typed

No fixed data type. Variable type can change anytime → NO type safety.

// JavaScript
let x = 20; // x is a number
x = "John"; // ✅ allowed! now x is a string
// no error — bug caught only at RUNTIME
✅ TypeScript — Statically Typed

Once a variable's type is fixed, it cannot change → Type Safety guaranteed.

// TypeScript
let x = 20; // x locked as number
x = "John"; // ❌ Compile Error!
// Type 'string' not assignable to 'number'
Exam Point — Compile Time vs Runtime

JavaScript → errors found only at RUNTIME (while executing).
TypeScript → errors caught at COMPILE TIME (while writing/compiling) — bugs caught early!

Re-declaring with let twice? ❌ Not allowed in TS!
Assignment (same type) is fine.
Re-declaration (new type) is NOT.
💡 Why This Matters for QA Automation

Type safety = fewer runtime surprises in your Playwright / Selenium automation scripts → easier to maintain large test frameworks & find defects early.

⚡ Formula & Command Shortcut Zone

All the terminal commands you'll ever need for Day 1 — memorize this box!

// ---- VERIFY INSTALLATIONS ----
node -v // check Node.js version
node --version // alternate command
npm -v // check npm (Node Package Manager)
tsc --version // check TypeScript compiler version

// ---- INSTALL TOOLS (via npm) ----
npm install -g typescript // install TypeScript compiler
npm install -g tsx // install TypeScript executor

// ---- COMPILE & RUN (traditional) ----
tsc Day1/FirstDemo.ts // compile → generates FirstDemo.js
node Day1/FirstDemo.js // run the JS output

// ---- RUN DIRECTLY (fast way) ----
tsx Day1/FirstDemo.ts // runs .ts directly, no .js created ⭐
Fix for the #1 Beginner Error

Error: "cannot be loaded because running scripts is disabled on this system"

set-executionpolicy -scope currentuser -executionpolicy remotesigned

Run this once in the terminal → then tsc works forever after. 🔑

⌨️ VS Code Shortcut

Open terminal instantly: Ctrl + ` (backtick)  |  Increase/decrease font: Ctrl +/- (Mac: Cmd +/-)

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "Superset" Question

If asked "Is all valid JS code also valid TS code?" → YES (because TS is a superset). But reverse is not always true (TS has extra syntax JS doesn't understand).

Trick 2 — Compile-time vs Run-time

Interviewers love asking: "Where does TypeScript catch errors?" → Answer: Compile time, not runtime. This is the #1 reason to prefer TS in automation frameworks.

Trick 3 — File Extensions

.ts = TypeScript source  |  .js = compiled JavaScript output. Never confuse which one you write vs which one you run via node.

Trick 4 — npm's Real Role

npm (Node Package Manager) comes bundled with Node.js — it's the tool used to install everything else (TypeScript compiler, tsx, Playwright, etc.) via npm install -g <package>.

Final One-Page Memory Sheet

🧩 Core Definition

TypeScript = Superset of JavaScript (Microsoft). Adds type safety + extra features. Compiles to plain JS.

🛡️ Type Safety

JS = dynamic (type can change, no safety). TS = static (type locked, errors caught at compile time).

⚙️ Setup Trio

Node.js (runtime) + TSC (compiler) + VS Code (editor). Optional 4th: tsx (direct execution).

💻 Key Commands

node -v · npm -v · npm install -g typescript · npm install -g tsx · tsc file.ts · node file.js · tsx file.ts

🔥 Common Error Fix

"Running scripts disabled" → run set-executionpolicy -scope currentuser -executionpolicy remotesigned once.

New folder → Open in VS Code → New .ts file → console.log("...") → Auto Save ON → Terminal (Ctrl+`) → Run.
