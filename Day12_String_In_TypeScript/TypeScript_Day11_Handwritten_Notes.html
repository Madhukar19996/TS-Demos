What is a String?

📖 Definition

A string is a group of characters / text value. Even numbers inside quotes count as strings! Strings, just like arrays, have index-based characters starting at 0.

3 Ways to Write a String
let str1: string = 'hello'; // single quote
let str2: string = "hello"; // double quote
let str3: string = `hello`; // backtick

All print identically — Java only allows double quotes; TS/JS gives you all three.

🚨 When Backtick is MANDATORY, Not Optional
let number = 10;
console.log("number is number"); // ❌ prints literal text "number is number"
console.log("number is ${number}"); // ❌ still invalid in double quotes
console.log(`number is ${number}`); // ✅ "number is 10"

Rule: To embed a variable's VALUE inside a string, you MUST use backticks with ${}. 90% of the time single/double quotes are fine — but this specific case needs backtick.

📏 length & 🔠 Case Conversion

length — Attribute, Not a Method
let str = "Hello, TypeScript!";
console.log(str.length); // 18 — counts spaces & symbols too!

No parentheses — it's a property, just like array's .length.

toUpperCase()
str.toUpperCase();
// "HELLO, TYPESCRIPT!"
toLowerCase()
str.toLowerCase();
// "hello, typescript!"

Both return a NEW string — the original str stays unchanged (immutability — more on this later).

🔍 charAt() vs indexOf() — Exact Opposites

MethodTakes as InputReturns

let str = "Hello TypeScript!";
str.charAt(4); // "o" — character AT index 4
str.indexOf("Type"); // 6 — index WHERE "Type" starts
Memory Trick 🧠
charAt = "give me the CHARACTER at this spot" / indexOf = "give me the SPOT of this text"

To capture the LAST character of a string, your end index must be string.length — since it's exclusive, this correctly includes the final character (at index length - 1).

✅ includes() / startsWith() / endsWith()

📖 All Three Return Boolean (true/false)
let str = "Hello TypeScript!";
str.includes("TypeScript"); // true
str.includes("ABC"); // false
str.startsWith("Hello"); // true
str.endsWith("!"); // true
str.startsWith("ABC"); // false
🚨 Case Sensitivity!

All string methods are case sensitive — "TYPESCRIPT" ≠ "TypeScript". includes("TYPESCRIPT") would return false even though the text exists in different casing.

includes() = Java's .contains() — extremely common in automation for assertions/verifications.

6

🔄 replace()

let str = "Hello TypeScript!";
let updated = str.replace("TypeScript", "World");
console.log(updated); // "Hello World!"
console.log(str); // "Hello TypeScript!" — UNCHANGED

Returns a new string with the replacement applied — original stays exactly the same (immutability again).

7

🔗 split() — String → Array

📖 Breaks a String into Parts Based on a Delimiter
let str = "hello typescript";
let words: string[] = str.split(" "); // delimiter = space
console.log(words); // ["hello", "typescript"]
console.log(words[0]); // "hello"
console.log(words[1]); // "typescript"
Real Use Case — Splitting "email,password"
let myString = "abc@gmail.com,xyzabc";
let arr = myString.split(","); // delimiter = comma
console.log(arr[0]); // "abc@gmail.com"
console.log(arr[1]); // "xyzabc"

Very common in data-driven automation — parsing CSV-like test data strings.

split() returns an ARRAY — always store the result in an array variable.

🧹 trim() / trimStart() / trimEnd()

MethodRemoves Spaces From
trim()Both beginning AND end
trimStart()Only the beginning
trimEnd()Only the end
let myString = " Welcome to TypeScript ";
myString.trim(); // "Welcome to TypeScript" (no spaces either side)
myString.trimStart(); // "Welcome to TypeScript " (trailing spaces remain)
myString.trimEnd(); // " Welcome to TypeScript" (leading spaces remain)
Java has only trim(). Python has lstrip/rstrip. TS/JS uses trimStart/trimEnd — different naming per language!
9

➕ concat() — Joining Strings

let str1 = "Welcome";
let str2 = "to TypeScript";
let combined = str1.concat(str2); // "Welcome to TypeScript"

// chaining for 3+ strings:
let str3 = "and JavaScript";
let all = str1.concat(str2).concat(str3);
🚨 concat() Takes Only ONE Argument

To join 3+ strings, you must chain multiple .concat() calls — it doesn't accept multiple parameters like array's concat does.

Alternative: + Operator (works, but not recommended for strings)
let joined = str1 + " " + str2; // works, but concat() is preferred for clarity

+ is fine for strings but risky — between numbers it does arithmetic instead, so mixing types with + can cause confusion.

10

🔒 String Immutability — Critical Concept

📖 Definition

Strings are immutable — no string method can change the original string. Every method returns a brand-new string, leaving the original untouched.

let str1 = "welcome";
let modified = str1.concat(" to TypeScript");
console.log(modified); // "welcome to TypeScript"
console.log(str1); // "welcome" — STILL unchanged!
⭐ Same Concept Applies to Numbers Too
let number = 10;
let result = number + 5;
console.log(result); // 15
console.log(number); // 10 — unaffected by the operation

Mutable vs Immutable: if an operation CAN'T change the original value, that's immutability. Java also treats strings as immutable — this is a shared concept across languages.

📄 Multi-line Strings

❌ Not Possible with Single/Double Quotes
let str = "Welcome to
TypeScript"; // ❌ Error — breaks the string
✅ Backtick Enables Multi-line
let multiLine = `Welcome to
TypeScript`;
console.log(multiLine);
// Welcome to
// TypeScript (printed across 2 lines)

Another reason backtick strings (template literals) are so widely preferred in modern TS/JS.

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "What is string immutability?"

String methods never modify the original string — they always return a new one. Have the concat() example ready.

Trick 2 — "Difference between charAt() and indexOf()?"

charAt takes an index, returns a character. indexOf takes a string, returns an index. Opposite direction.

Trick 3 — "Is substring's end index inclusive?"

No — exclusive, same rule as array slice. Always subtract 1 mentally to know the last included character.

Trick 4 — "When must you use backticks over quotes?"

Whenever embedding a variable's value inside a string (${var}), or writing a multi-line string. Single/double quotes fail in both cases.

Every string method returns a NEW string — the original is never modified.
