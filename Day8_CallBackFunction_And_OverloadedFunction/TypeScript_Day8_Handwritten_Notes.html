📞 What is a Callback Function?

📖 Definition

A callback function is a function passed as an argument to another function, and gets executed later — not called immediately when passed.

Basic Example
function showMessage(message: string): void {
  console.log(message);
}

function greet(name: string, smg: (msg: string) => void): void {
  console.log(name);
  smg("hello"); // invoking the callback here
}

greet("John", showMessage);
// Output: John, then hello

showMessage is passed without calling it (no brackets!) — it's invoked inside greet later, via the parameter name it was received as.

🚨 Callback Parameter Syntax — Not a Plain Type!

When receiving a function as a parameter, you must specify its full function signature, not just void:

// ❌ Wrong — this is only valid for a function's own return type
function greet(name: string, smg: void) { }

// ✅ Correct — describe the callback's params and return type
function greet(name: string, smg: (msg: string) => void) { }

📌 Worked Example — Callback with Result

function displayResult(result: number): void {
  console.log(result);
}

function sum(a: number, b: number, callback: (result: number) => void): void {
  let result = a + b;
  callback(result); // pass computed result INTO the callback
}

sum(10, 20, displayResult);
// Output: 30
The Flow
  1. Define displayResult — a normal function.
  2. Pass it (name only, no parentheses) as an argument into sum.
  3. Inside sum, compute the answer, then call the callback with that answer.

You can pass multiple callback functions too — just separate them with commas, each with its own signature.

⏳ Why Callbacks Matter: Sync vs Async

SynchronousAsynchronous
Code runs in the exact sequence writtenLater instructions may execute before earlier ones finish
Default in most languages (Java, Python)Default challenge in JS/TypeScript
Predictable orderUsed in API calls, file handling, event handling
Where Callbacks Help

Callbacks let you force one function to run only after another completes — turning async-prone code into a controlled, synchronous-like sequence.

🚨 Automation Reality Check

In pure JS/TS development, callbacks solve async problems. But in Playwright automation, this is handled instead via async/await keywords — so callback functions are rarely used directly in automation scripts, even though the concept is a common interview topic.

🔁 Function Overloading — What & Why

📖 Definition

Function overloading = defining multiple versions of a function with the SAME name, but different parameter types, different parameter counts, or different return types.

Note 🧠
Java has "method overloading" (needs a class). TypeScript uniquely also supports plain "function overloading" — no class required!
The 3-Step Rule — Memorize This!
1
Write the SIGNATURES

Function declarations with no body — just name, params, return type, ending in ;

2
Implement ONE function

A single implementation that satisfies ALL signatures — never multiple bodies!

3
Call the function

Call with any parameter combination matching one of the declared signatures.

6

Example 1 — Different Parameter Types

// STEP 1: signatures (no body)
function getInfo(id: number): string;
function getInfo(name: string): string;

// STEP 2: single implementation covering both
function getInfo(param: number | string): string {
  if (typeof param === "number") {
    return `User ID is ${param}`;
  } else {
    return `User name is ${param}`;
  }
}

// STEP 3: calling with either type
console.log(getInfo(101)); // User ID is 101
console.log(getInfo("John")); // User name is John
🚨 Backtick Required for Value Extraction

To embed param's value inside the returned string, you must use backticks: `User ID is ${param}`. Single/double quotes will NOT extract the variable's value — they'll only print the literal text.

7

Example 2 — Different Number of Parameters

// STEP 1: signatures
function add(a: number, b: number): number;
function add(a: number, b: number, c: number): number;

// STEP 2: single implementation — 3rd param made OPTIONAL
function add(a: number, b: number, c?: number): number {
  if (c !== undefined) {
    return a + b + c;
  }
  return a + b;
}

// STEP 3: calling
console.log(add(10, 20)); // 30
console.log(add(10, 20, 30)); // 60
Key Trick

Make the extra parameter optional (c?: number) in the implementation so ONE function body can satisfy BOTH signatures. Check with c !== undefined to decide behavior — else is optional here since a + b always needs to run anyway.

8

Example 3 — Different Return Types

// STEP 1: signatures
function processInput(str: string): string;
function processInput(num: number): number;

// STEP 2: single implementation
function processInput(input: string | number): string | number {
  if (typeof input === "string") {
    return input.toUpperCase();
  } else {
    return input * input;
  }
}

// STEP 3: calling
console.log(processInput("hello")); // HELLO
console.log(processInput(5)); // 25

Both parameters AND return type use union types (string | number) — everything about the signature can vary, as long as one implementation handles it all.

9

Example 4 — Three Different Types (string/number/boolean)

function greet(name: string): string;
function greet(age: number): string;
function greet(isMarried: boolean): string;

function greet(value: string | number | boolean): string {
  if (typeof value === "string") {
    return `Hello ${value}`;
  } else if (typeof value === "number") {
    return `You are ${value} years old`;
  } else {
    let result: string = value ? "married" : "single";
    return result;
  }
}

console.log(greet("John")); // Hello John
console.log(greet(30)); // You are 30 years old
console.log(greet(true)); // married
console.log(greet(false)); // single

Ternary operator used inside to compactly return "married" or "single" based on the boolean value.

10

✅❌ Valid vs Invalid Overloading Rules

✅ Allowed
  • Same function name across all signatures
  • Different parameter TYPES
  • Different NUMBER of parameters (use optional params)
  • Different RETURN types
  • One single implementation that satisfies every signature
❌ Not Allowed
  • Writing signatures with NO implementation at all
  • Implementation's return type doesn't match ANY signature's return type
  • Two signatures with identical parameter types — "cannot overload identical signature" error
  • Implementation's parameter types incompatible with a signature
  • Inconsistent optional/mandatory placement across signatures (e.g., param B optional in one, mandatory in another)
🚨 Golden Rule of Overloading

The single implementation must be a superset that satisfies every declared signature — in parameter types, parameter count, AND return type simultaneously. If even one signature can't be satisfied, overloading isn't possible for that case.

11

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "What is a callback function, with example?"

A function passed as an argument to another function and executed later (not immediately). Classic interview ask — have a code example ready.

Trick 2 — "How do you receive a function as a parameter in TS?"

Specify its full signature: paramName: (argType) => returnType — not just a plain type like void.

Trick 3 — "Difference between function overloading and method overloading?"

Function overloading = standalone functions, no class needed (TS-specific). Method overloading = belongs to OOP/polymorphism, needs a class (found in Java too).

Trick 4 — "How many implementations does an overloaded function have?"

Always exactly ONE — regardless of how many signatures are declared. This is the #1 rule people get wrong.

Final One-Page Memory Sheet

📞 Callback Function

Passed as an argument, invoked inside the receiving function later — not called immediately at pass-time.

⏳ Sync vs Async

Sync = sequential execution. Async = later steps may run before earlier ones finish. Callbacks bring order to async code.

🔁 Overloading — 3 Steps

1) Write signatures (no body). 2) One implementation satisfying all. 3) Call with matching params.

🎯 What Can Differ

Parameter types, parameter count, return types — name must always stay the same.

✅ Must Satisfy All

Single implementation's params & return type must cover every declared signature using union types / optional params.

❌ Invalid Cases

No implementation, mismatched return type, identical signatures, or inconsistent optional placement.

✨ "One name, many faces — that's overloading. Pass now, run later — that's a callback." ✨
