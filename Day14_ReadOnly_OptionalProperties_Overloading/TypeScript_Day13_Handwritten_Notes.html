🔒 readonly Properties

📖 Definition

Value can be assigned ONLY ONCE — through the constructor. After that, it can be read any number of times, but never modified.

class Student {
  readonly studentId: number;
  name: string;

  constructor(id: number, name: string) {
    this.studentId = id; // ✅ allowed — inside constructor, first assignment
    this.name = name;
  }
}

let s1 = new Student(101, "John");
s1.studentId = 111; // ❌ Error: Cannot assign to 'studentId' — read-only property
🚨 Don't Confuse with Java's `final`!

Similar spirit, but TS's readonly is specifically for class/object properties — different syntax and rules from other languages. Don't map it 1:1 onto Java concepts.

3

❓ Optional Properties

📖 Definition

Marked with ? — the value is not mandatory. If skipped, defaults to undefined.

class Student {
  readonly studentId: number;
  name: string;
  email?: string; // optional property

  constructor(id: number, name: string, email?: string) { // also optional here!
    this.studentId = id;
    this.name = name;
    this.email = email;
  }
}
🚨 Must Mark Optional in BOTH Places!

Declaring the property with ? is not enough — the constructor parameter must ALSO be marked optional with ?, otherwise TypeScript still demands the argument at call time.

Common Pattern — Guard Before Printing
displayInfo(): void {
  console.log(`Student ID: ${this.studentId}`);
  console.log(`Name: ${this.name}`);
  if (this.email) {
    console.log(`Email: ${this.email}`);
  } else {
    console.log("Email not provided");
  }
}

Without this check, an unpassed optional value prints literal undefined instead of something meaningful.

4

🌐 static Properties & Methods

📖 Definition

A static property/method is SHARED across ALL objects — it doesn't belong to any single object. Applies to both properties AND methods.

class Student {
  static schoolName: string = "Greenwood High"; // shared by ALL students

  static changeSchoolName(newName: string): void {
    Student.schoolName = newName; // use CLASS NAME, not 'this'
  }
}
⭐ TOP INTERVIEW QUESTION — The 3 Golden Rules of static
  1. Shared across all objects — one copy, not per-object copies
  2. Accessed via class name directly — Student.schoolName, never this.schoolName
  3. Modified through ANY object's method call, but the change reflects everywhere since it's the same shared value
🚨 Can't Use `this` for Static Members!
changeSchoolName(newName: string): void {
  this.schoolName = newName; // ❌ Error: use static member via class name
  Student.schoolName = newName; // ✅ correct
}

this refers to the current object instance — but static members don't belong to any instance, so this can't reach them.

🚨 Also Can't Access via Object Name!
s1.schoolName; // ❌ Error — even through an object, not allowed
Student.schoolName; // ✅ only way to access

Different from Java! Java allows accessing static members through an object reference too — TypeScript strictly requires the class name only.

Memory Trick 🧠
static = a shared notice board 📋 — anyone can update it (any object), everyone sees the same update instantly.
5

🔁 Constructor Overloading

📖 Same Pattern as Function Overloading — Applied to Constructors

Multiple constructor signatures, but ONE implementation that satisfies all of them — using optional parameters.

class Calculator {
  // signatures:
  constructor(); // default — no params
  constructor(a: number, b: number); // parameterized

  // single implementation — both params optional
  constructor(a?: number, b?: number) {
    if (a !== undefined && b !== undefined) {
      console.log(`Sum of a and b: ${a + b}`);
    } else {
      console.log("Default constructor called");
    }
  }
}

let calc1 = new Calculator(); // "Default constructor called"
let calc2 = new Calculator(10, 20); // "Sum of a and b: 30"

Constructor runs automatically at object creation — no explicit call needed, unlike regular methods.

6

🔁 Method Overloading (Inside a Class)

class Calculator {
  // signatures:
  add(a: number, b: number): number;
  add(a: number, b: number, c: number): number;

  // single implementation — 3rd param optional
  add(a: number, b: number, c?: number): number {
    if (c !== undefined) {
      return a + b + c;
    }
    return a + b;
  }
}

console.log(calc1.add(10, 20)); // 30
console.log(calc1.add(10, 20, 30)); // 60
🚨 Methods Need EXPLICIT Calls — Unlike Constructors!

Constructors auto-run at new. Methods (even overloaded ones) must always be called explicitly via an object: calc1.add(...). Overloading only affects WHICH signature matches, not HOW it's invoked.

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "Can you reassign a readonly property after the constructor?"

No — compile-time error. Assignment is allowed only inside the constructor, and only once.

Trick 2 — "Why can't you use `this` for static members?"

this refers to the specific object instance. Static members don't belong to any single instance — they belong to the class itself, so only the class name reaches them.

Trick 3 — "How is TS's static different from Java's?"

Java allows accessing static members through an object reference too. TypeScript is stricter — only the class name works, not objectName.staticMember.

Trick 4 — "What's the rule for constructor/method overloading?"

Multiple signatures, but exactly ONE implementation that satisfies all of them — typically achieved by making the extra parameters optional.

🔁 Quick Revision Summary

readonly = assign once via constructor, never modify after
optional (?) = skippable, must mark in BOTH property & constructor param
static = shared across all objects, applies to props AND methods
Access static only via ClassName, never this or objectName
Constructor overloading: multiple signatures, one impl, optional params
Method overloading: same idea, but always called explicitly via object
★

Final One-Page Memory Sheet

🔒 readonly

Set once inside constructor via this.x = x. Any later reassignment throws a compile error.

❓ optional

x?: type on both property AND constructor param. Skipped value becomes undefined — guard before printing.

🌐 static

Shared value/method across all objects. Access only via ClassName.member, never this or an object reference.

🔁 Constructor Overloading

Multiple signatures, one implementation with optional params. Auto-invoked at `new`.

🔁 Method Overloading

Same rule as constructors, but always requires an explicit call: object.methodName(...).
