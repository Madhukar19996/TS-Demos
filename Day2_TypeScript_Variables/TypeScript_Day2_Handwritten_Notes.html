Comments in TypeScript

📖 Why Comments?

Two purposes: improve readability (explain your code to others) and disable code temporarily without deleting it.

✏️ Single-Line Comment
// this line won't execute
console.log("Welcome");

Shortcut (Windows): Ctrl + /   |   Mac: Cmd + /

✏️ Multi-Line Comment
/* this whole
block is
commented */

Shortcut (Windows): Shift + Alt + A   |   Mac: Shift + Option + A

Same shortcut comments AND uncomments — just toggle it! 🔁
Semicolon optional in TS/JS — unlike Java's mandatory ;
VS Code Only!

These shortcuts are VS Code specific — Eclipse or other IDEs use different key combos.

What is a Variable?

📖 Definition

A variable is a container that can hold / store some data.

let x = 10; // x → variable, 10 → value
Naming a Variable
↙
Use meaningful names
e.g. studentName, not just "s"
↓
Prefer lowercase
(camelCase standard)
↘
Files/folders →
start with Uppercase (convention)
🧾 Full Syntax (with data type — optional)
keyword variableName : dataType = value;

// example
let age : number = 30;

Data type is OPTIONAL in TS/JS — you can also write:

keyword variableName = value;

// example
let age = 30;
Printing a Variable — Common Beginner Mistake

console.log("age") → prints the literal string "age".
console.log(age) → prints the variable's value (30). No quotes for variables!

The 3 Keywords: var, let, const

TS/JS give us 3 ways to declare a variable. Golden rule for when to use which:

🚫 var

  • AVOID in modern TS/JS
  • Function-scoped → unpredictable
  • Allows redeclaration (breaks type safety)

🔁 let

  • Use when value keeps changing
  • Block-scoped ✅
  • No redeclaration, but reassignment OK

🔒 const

  • Use when value never changes
  • Block-scoped ✅
  • Must initialize at declaration; no reassignment
Memory Trick 🧠
"const = constant = can't change"
let = value keeps "letting go" and changing 😄

Battle Round 1️⃣ — Scope

📖 Scope = Accessible / Visible Area

TS/JS has only 2 types of scope: Functional Scope and Block Scope.

var
Functional Scope
vs
let / const
Block Scope
❌ var — Functional Scope
function whereScope() {
  if (true) {
    var msg = "Hello World";
  }
  console.log(msg); // ✅ works!
}

Accessible anywhere inside the function — even outside the if block. This causes unexpected bugs!

✅ let/const — Block Scope
function blockScope() {
  if (true) {
    let msg = "Hello";
    console.log(msg); // ✅ inside block
  }
  console.log(msg); // ❌ Error! out of scope
}

Only accessible within the { } block it was created in.

3-Variable Test
if (true) {
  var num1 = 10; let num2 = 20; const num3 = 30;
}
console.log(num1); // ✅ 10 (functional scope)
console.log(num2); // ❌ Error (block scope)
console.log(num3); // ❌ Error (block scope)

Battle Round 2️⃣ — Declaration & Value Assignment

📖 Declaration vs Initialization

Declaration = just naming the variable (no value).
Initialization = assigning a value to it.

KeywordCan declare WITHOUT initializing?Value if printed uninitialized
var✅ Yesundefined
let✅ Yesundefined
const❌ No — must assign value at declarationCompile Error
// var & let — OK
var x; console.log(x); // undefined
x = 30; console.log(x); // 30

// const — NOT OK
const jed; // ❌ Error: must be initialized
const jed = 50; // ✅ correct
TS assigns type any to a variable declared with no value & no type!
6

Battle Round 3️⃣ — Redeclaration

📖 Redeclaration

Declaring the same variable name again in the same scope.

❌ var — Redeclaration ALLOWED
var city = "New York";
var city = "Los Angeles"; // ✅ allowed
console.log(city); // Los Angeles

This is exactly why var breaks type safety — same variable, silently overwritten.

✅ let / const — Redeclaration BLOCKED
let country = "India";
let country = "US"; // ❌ Error!
Cannot redeclare block-scoped variable 'country'

Same error for const.

7

Battle Round 4️⃣ — Reinitialization (Reassignment)

📖 Reassignment

Changing the value of an already-declared variable (not redeclaring the keyword).

✅ var / let — Reassignment ALLOWED
let age = 25;
age = 30; // ✅ allowed
console.log(age); // 30
❌ const — Reassignment BLOCKED
const age = 25;
age = 30; // ❌ Error!
Cannot assign to 'age' — it is a constant
Don't Confuse: Redeclaration vs Reassignment

Redeclaration = writing the keyword again (let x twice) → blocked for let/const.
Reassignment = just changing the value (x = newValue) → allowed for let, blocked for const.

8

Battle Round 5️⃣ — Hoisting

📖 Hoisting

Accessing a variable BEFORE it's declared/assigned in the code.

var → returns undefined
console.log(a); // undefined
var a = 10;
console.log(a); // 10
let / const → Error ("not initialized")
console.log(b); // ❌ Cannot access before initialization
let b = 10;
Memory Trick 🧠
var = "silent undefined" 🤫 | let/const = "loud error" 📢

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "Can you redeclare a variable in TS?"

Depends on keyword! var → Yes, let/const → No. Always specify which keyword when answering.

Trick 2 — "What does console.log(x) print before declaration?"

var → undefined. let/const → throws a ReferenceError (not initialized). Different outcomes — don't mix them up!

Trick 3 — "Which keyword should never be used in modern TS?"

Answer: var — always mention BOTH reasons (functional scope + redeclaration) for full marks.

Trick 4 — Const ≠ Immutable Object (gotcha for later!)

const prevents reassigning the variable itself — but if it holds an object/array, the object's contents can still change. (Preview for upcoming data-types class.)
