📖 When to Use Conditional Statements

Whenever you want to execute a specific group of statements based on a certain condition. Syntax is nearly identical to Java.

2

1️⃣ Only-if Statement

if (condition) {
  // executes only if condition is TRUE
}

Condition must always evaluate to true/false (relational/logical operators). If false → block simply skipped, nothing happens.

Example — Eligibility Check
let age: number = 20;
if (age >= 18) {
  console.log("You are eligible to vote");
}

If age = 15, condition is false → no output at all (no else to fall back on).

let num: number = 10;
if (num % 2 === 0) {
  console.log(`${num} is even number`);
} else {
  console.log(`${num} is odd number`);
}
🚨 Common Mistake — Wrong Quote Type

To embed a variable's value inside a printed string, you MUST use backticks `${num}` — single/double quotes will throw an error or print literally. Alternative: use + concatenation with single/double quotes.

3️⃣ Nested if-else (else-if chain)

📖 When to Use

When you have multiple conditions to check, one after another, top to bottom. Once ANY condition is true, the rest are skipped entirely.

if (condition1) { /* stmt 1 */ }
else if (condition2) { /* stmt 2 */ }
else if (condition3) { /* stmt 3 */ }
else { /* default stmt */ }
marks >= 90?
↓ false
marks >= 75?
↓ false
marks >= 60?
↓ false
else → Grade D
Example — Grade Calculator
let marks: number = 80;
if (marks >= 90 && marks <= 100) {
  console.log("Grade A");
} else if (marks >= 75 && marks < 90) {
  console.log("Grade B");
} else if (marks >= 60 && marks < 75) {
  console.log("Grade C");
} else {
  console.log("Grade D");
}

marks=80 → Grade B (skips A, matches B, ignores C & D).

Example — Browser Selection (Automation Use Case!)
let browser: string = "chrome";
if (browser === "chrome") {
  console.log("Browser is Chrome");
} else if (browser === "firefox") {
  console.log("Browser is Firefox");
} else if (browser === "safari") {
  console.log("Browser is Safari");
} else {
  console.log("Some other browser");
}

Real automation use case — driver setup based on browser name. Uses === (strict equality) to check value + type.

4️⃣ switch-case Statement

📖 Key Difference: Condition vs Expression

if/else uses a condition (always true/false). switch uses an expression (can return anything — number, string, boolean).

switch (expression) {
  case value1:
    // statements
    break;
  case value2:
    // statements
    break;
  default:
    // statements
}
Example — Day of the Week
let day: number = 3;
switch (day) {
  case 1: console.log("Monday"); break;
  case 2: console.log("Tuesday"); break;
  case 3: console.log("Wednesday"); break;
  // ... case 4 to 7 ...
  default: console.log("Invalid day");
}

day=3 → Wednesday. day=10 (no matching case, no default written) → no output at all.

🚨 CRITICAL: Why break is Mandatory!

Without break, switch-case "falls through" — it keeps executing the NEXT case(s) too, even though they don't match!

// day = 1, but NO break statements:
switch (day) {
  case 1: console.log("Monday"); // no break!
  case 2: console.log("Tuesday"); // no break!
  case 3: console.log("Wednesday");
}
// Output: Monday, Tuesday, Wednesday — ALL printed! 😱

break is a jumping statement (along with continue) — it exits the entire switch block immediately once a case matches.

switch with an Expression (not just a plain variable)
let x: number = 10, y: number = 5;
switch (x - y) { // expression: 10-5=5
  case 0: console.log("result is zero"); break;
  case 5: console.log("result is five"); break;
  case 10: console.log("result is ten"); break;
  default: console.log("result is something else");
}

default is optional — if omitted and nothing matches, simply no output.

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "Condition vs Expression — what's the difference?"

Condition (if/else) → must return true/false. Expression (switch) → can return any value type. This IS the core reason they're structured differently.

Trick 2 — "What happens if you forget break in switch?"

Fall-through bug — all subsequent cases execute regardless of match, until a break is hit or the switch ends. Always trace this carefully in code review questions.

Trick 3 — "Is default mandatory in switch?"

No — optional, just like else in if-else. If omitted and nothing matches, no error, just no output.

Trick 4 — "Nested if-else execution order?"

Always evaluated top to bottom. The moment one condition is true, its block runs and ALL remaining else-if/else are skipped — even if they'd also be true.

🔁 Quick Revision Summary

2 statement types: Conditional (decision) & Looping (iterative)
if → runs only when true, no fallback
if-else → true block OR false block, never both
nested if-else → top-to-bottom, first match wins
switch uses expression (any value), not condition
break is mandatory — prevents fall-through
default in switch = optional, like else
★

Final One-Page Memory Sheet

✅ if

Runs block only if condition true. No else = no fallback, silently skips if false.

↔️ if-else

True → if-block. False → else-block. Exactly one runs, never both.

🪜 nested if-else

Chain of else-if conditions, evaluated top-down. First true match wins, rest skipped.

🔀 switch-case

Matches an expression (any type) against case values. break exits; default is optional fallback.

🚨 break = mandatory

Without it, execution "falls through" into subsequent cases — a classic bug source.

🎯 Which to pick?

Few conditions / ranges → if-else. Many exact-value checks → switch-case (shorter, cleaner).

✨ "If it's true or false — use if. If it's one of many exact values — switch it!" ✨
