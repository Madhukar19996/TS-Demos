Proving It: Dynamic vs Static Typing

Interview favorite: "How do you PROVE TS is statically typed & JS is dynamic?" — with code, not just definitions.

❌ JavaScript (test.js) — Dynamic
let age = 30; // number
age = "hello"; // ✅ allowed! now string
console.log(age); // "hello"
console.log(typeof age); // "string"

No compile-time error — type freely changes.

✅ TypeScript (test.ts) — Static
let data = 10; // number
data = "hello"; // ❌ Error!
Type 'string' is not assignable to type 'number'

Type is locked the moment it's inferred/assigned.

🚨 The node vs tsx Trap!

Running a .ts file with node can silently execute even with type errors — because without explicit types, TS code looks just like JS. Node doesn't understand TS-only syntax (like explicit type annotations) at all.

Rule: Always run TypeScript files using tsx, never node. Only after compiling to real .js should you use node.

Proving It: Type Safety

📖 Concept

Dynamic typing ⇄ No type safety. Static typing ⇄ Type safety. These two ideas are directly linked.

❌ JavaScript — No Type Safety
let result = "5" + 3;
console.log(result); // "53" (concatenation!)
// No compile-time error — silently wrong

Expected 8 (addition), got "53" (string concat) — and JS never warns you.

✅ TypeScript — Type Safety (with explicit types!)
let num1: string = "5";
let num2: number = 3;
let result = num1 + num2;
// run with node → ❌ Error (doesn't understand types)
// run with tsx → catches the logical mismatch
🔑 Golden Rule

Type safety in TS only fully kicks in when you explicitly specify data types. Without explicit types, TS quietly behaves just like JS (type inference fills the gap, but loosely-written code can still slip through).

3 Key Terms: Type, Annotation, Type Inference

let age : number = 30;
↑keyword ↑variable ↑annotation ↑value
🏷️ Annotation

Explicitly specifying the data type using : type. You tell TypeScript what type to expect.

let age: number = 30;
🔮 Type Inference

No explicit type given — TypeScript auto-detects the type from the assigned value, at compile time.

let age = 30;
// TS infers: number
⚡ Interview Gold — Annotation vs Inference

Annotation = YOU explicitly declare the type.
Inference = TYPESCRIPT automatically assigns the type based on the value.
They're exact opposites — never confuse them!

Memory Trick 🧠
Annotation = "I ANNOUNCE the type" 📢
Inference = "TS INFERS/guesses the type" 🔍

🔢 The 7 Primitive Types — Deep Dive

1️⃣ number

Both integers AND decimals use the same type.

let age: number = 30;
let price: number = 25.5;

2️⃣ string

Text data. 3 ways to write: single quotes, double quotes, backticks.

let a = "John"; let b = 'Kennedy';
let c = `Hi ${a} ${b}`; // template literal

3️⃣ boolean

Only true or false. Used heavily in conditions/loops.

let isStudent: boolean = true;

4️⃣ null & undefined

TS-specific. Used when value is empty/unknown or not yet assigned.

let x: null = null;
let y: undefined = undefined;

5️⃣ any

Accepts ANY type — but breaks type safety. Use sparingly!

let val: any = "hi";
val = 5; val = true; // all OK

6️⃣ union type

Restrict to a chosen set of types using |. Safer than any.

let id: number | string | boolean;
id = "abc"; id = 123; id = true; // ✅

7️⃣ void

Used for functions (not variables) that don't return anything. Optional to write.

function show(): void {
  console.log("Welcome");
}

function sum(x: number, y: number): number {
  return x + y; // has return type → not void
}

🧵 String Concatenation — Backtick Magic

❌ Wrong way (comma inside variable)
let greeting = "Hello", firstName, lastName;
// ❌ Error! comma only works in console.log
✅ Right way — Template Literal (backtick)
let firstName = "John";
let lastName = "Kennedy";
let greeting = `Hello ${firstName} ${lastName}`;
console.log(greeting); // Hello John Kennedy
Rule of Thumb

console.log("a", b) → comma works fine for printing.
But to store the combined result in a variable, you MUST use backticks `...${var}...` — this is called a template literal. Very common in data-driven test automation!

7

📌 Important Worked Examples

Checking a Variable's Type — typeof
console.log(typeof age); // "number"
console.log(typeof(age)); // same — brackets optional
Compile-Time Error: Using a Variable Before Assignment
let price: number;
console.log(price); // ❌ 'price' is used before being assigned
// (still returns "undefined" if force-run)
Custom Output Formatting with Comma
console.log("age:", age); // age: 30
console.log("is student", isStudent); // is student true

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "Prove TS is statically typed"

Show code: assign a number, then try re-assigning a string → point to the compile-time error message. That IS the proof.

Trick 2 — "Why does node sometimes run a .ts file with errors in it?"

Because node doesn't understand TS-only syntax (like : number) — it just skips over what looks like plain JS. Always use tsx to properly validate TypeScript.

Trick 3 — "Difference between null and undefined?"

null = intentionally empty/unknown value. undefined = variable declared but never assigned a value. Both are unique TS-specific primitive types.

Trick 4 — "When to use union type instead of any?"

Use union when you know the limited set of possible types (e.g., number | string). Use any only as a last resort — it fully breaks type safety.

Trick 5 — "Is void mandatory for functions with no return?"

No — void is optional in TS (unlike Java). Still good practice to write it explicitly for readability.
