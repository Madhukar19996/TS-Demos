What is an Object? — Start of OOP! 🎉

📖 Three Layers of Definition

Real world: anything with properties + behavior (a human, an animal, a phone).
Java/Python: object = variables + methods.
TS/JS (extra): object = a collection of key-value pairs — properties as keys, methods as function-values.

Object Example: Employee
↙
Properties
name, age, salary, job
↘
Behavior (methods)
getDetails(), calcBonus()
4 Ways to Create Objects in TS 🧠
1) Object type   2) Inline type object   3) Type alias   4) Class (most used!)
2

1️⃣ Approach: Object Type (Direct)

📖 Directly Assign Values — Works in JS AND TS
let employee = {
  name: "John",
  age: 30,
  salary: 50000,
  job: "Engineer",
  getDetails: function(): string {
    return `${this.name} is a ${this.job} earning ${this.salary}`;
  }
};

Use colon (:) for key-value pairs, not =. Inside a method, access properties with this.propertyName — NOT the bare name.

🚨 Don't Type-Annotate as `object`!
let employee: object = { name: "John" };
console.log(employee.name); // ❌ Error: property doesn't exist on type 'object'

If you explicitly annotate with the generic object keyword, TypeScript blocks direct property access! Just skip the annotation — by default it's still treated as an object (via type inference).

3

🔑 Accessing & Modifying Object Data

Approach 1 — Dot Notation (most common)
console.log(employee.name);
console.log(employee.getDetails());
employee.job = "Manager"; // modifying a value
Approach 2 — Bracket Notation
console.log(employee["name"]);
console.log(employee["getDetails"]());
employee["job"] = "Manager";

Key must be in quotes inside brackets.

Both notations work identically — dot notation is used far more often in practice.
4

2️⃣ Approach: Inline Type Object (TS Only)

📖 Declare Structure First, Assign Data After
// STEP 1: declare structure (types only, no values)
let student: { name: string; age: number; grade: string; getSummary: () => string; };

// STEP 2: assign the data separately
student = {
  name: "Scott",
  age: 15,
  grade: "A",
  getSummary: function(): string {
    return `${this.name} is ${this.age} years old and scored grade ${this.grade}`;
  }
};

TypeScript ONLY — explicit data types make this unusable in plain JavaScript.

🚨 The Big Problem — Repetition!

To create a second student object, you must re-type the ENTIRE structure again from scratch. For 10 students, you repeat the structure 10 times. This repetition is exactly what the next approach solves.

5

3️⃣ Approach: Type Alias (Reusable Structure) ⭐

📖 Define Structure ONCE, Reuse for MANY Objects
// define the structure ONCE using 'type'
type Product = {
  name: string;
  price: number;
  getInfo: () => string;
};

// reuse it for MULTIPLE objects
let book1: Product = {
  name: "Learn Java", price: 300,
  getInfo: function(): string { return `${this.name} costs ${this.price}`; }
};
let book2: Product = { name: "Learn Python", price: 500, getInfo: function() { return `${this.name} costs ${this.price}`; } };
let book3: Product = { name: "Learn JavaScript", price: 600, getInfo: function() { return `${this.name} costs ${this.price}`; } };

Solves the repetition problem! Declare once with type, then just tag every new object with : Product. TS-only feature.

6

🧬 Intersection Types — Combining Types

📖 Combine Multiple Types Using &
type Personal = { name: string; age: number; };
type Contact = { email: string; phone: number; };

// combine both + add an extra method
type Candidate = Personal & Contact & {
  getContactInfo: () => string;
};

let candidate: Candidate = {
  name: "Scott", age: 25, email: "scott@mail.com", phone: 9876543210,
  getContactInfo: function(): string {
    return `${this.name} can be contacted at ${this.email} or ${this.phone}`;
  }
};

The & operator merges ALL properties from every combined type into one — Candidate gets everything from Personal + Contact + its own addition.

Union (|) = "one OR the other". Intersection (&) = "combine ALL of them together". Opposite concepts!

🔁 Iterating Object Properties — for...in

for (let key in book3) {
  console.log(book3[key as keyof typeof book3]);
}
// prints each property value one after another

Rarely used in practice — one loop only works within a single object; you can't loop across multiple objects at once this way. Most of the time, direct console.log() calls are simpler.

Class is a logical entity (the blueprint). Object is a physical entity created FROM that blueprint. One class → many independent objects.

🏗️ Creating a Class

class Person {
  ssn: string;
  firstName: string;
  lastName: string;

  constructor(ssn: string, firstName: string, lastName: string) {
    this.ssn = ssn;
    this.firstName = firstName;
    this.lastName = lastName;
  }

  getFullName(): string {
    return this.firstName + " " + this.lastName;
  }

  getDetails(): string {
    return `SSN: ${this.ssn}, Name: ${this.getFullName()}`; // method calling another method
  }
}
🚨 Class Body Uses SEMICOLONS, Not Commas!

Unlike object literals (which use , between key-value pairs), class properties are separated with semicolons (;) — a common syntax mix-up when switching from objects to classes.

Constructor — Not JS's Class-Name Rule!

In Java, the constructor must match the class name exactly. In TS/JS, we always use the keyword constructor — regardless of the class name.

🚨 "this.ssn = ssn" — Why the `this` Keyword Matters
constructor(ssn: string) {
  ssn = ssn; // ❌ ambiguous, doesn't actually assign to class property
  this.ssn = ssn; // ✅ explicitly targets the CLASS property
}

When the parameter name and class property name are identical, this.propertyName is the only way to tell TypeScript "assign to the CLASS's variable", not the local parameter.

11

🆕 Creating Objects from a Class — `new` Keyword

let person1 = new Person("111", "John", "Kennedy");
let person2 = new Person("222", "David", "DV");
let person3 = new Person("333", "Scott", "Smith");

console.log(person1.getDetails()); // SSN: 111, Name: John Kennedy
console.log(person2.getDetails()); // SSN: 222, Name: David DV
📖 The Golden Rule of Objects

Every object gets its OWN independent copy of the class's variables, constructor, and methods. person1, person2, person3 are completely separate — changing one never affects another, even though all three were built from the same class blueprint.

Memory Trick 🧠
Class = cookie cutter 🍪. Objects = individual cookies — same shape, but each one is separate and edible on its own!
12

⚡ Exam-Trick & Frequently Tested Points

Trick 1 — "What's the definition of an object in TS/JS specifically?"

A collection of key-value pairs — not just "variables and methods" like Java/Python. This extra framing is TS/JS-specific.

Trick 2 — "Why does explicit `: object` typing break property access?"

TypeScript's generic object type doesn't know about your specific keys — so direct dot access on named properties is disallowed. Skip the annotation to rely on inference instead.

Trick 3 — "What problem does type alias solve over inline type objects?"

Eliminates repeating the same structure for every new object — define once with type, reuse for unlimited objects.

Trick 4 — "Constructor vs method — 3 key differences?"

Constructor: never returns a value, runs automatically on object creation, always named constructor. Method: can return, must be called explicitly, custom name.
